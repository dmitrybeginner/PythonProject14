# Трекер полезных привычек

Бэкенд-часть SPA веб-приложения для трекера полезных привычек на основе книги Джеймса Клира "Атомные привычки".

## Описание проекта

Приложение позволяет пользователям создавать, отслеживать и управлять своими полезными привычками. Включает интеграцию с Telegram для напоминаний и асинхронную обработку задач через Celery. Вся система полностью контейнеризирована с помощью Docker и разворачивается автоматически через CI/CD пайплайн на GitHub Actions.

## Основные возможности

- **Регистрация и авторизация пользователей** через JWT-токены
- **Создание и управление привычками** (CRUD операции)
- **Пагинация** списков привычек
- **Валидация данных** привычек согласно бизнес-правилам
- **Права доступа** (пользователи видят только свои привычки, публичные доступны всем)
- **Интеграция с Telegram** для привязки аккаунтов и получения напоминаний
- **Асинхронные задачи** через Celery для отправки напоминаний
- **API документация** через Swagger/ReDoc
- **Контейнеризация** всех сервисов (Django, PostgreSQL, Redis, Celery, Nginx)
- **Автоматическое развертывание** (CI/CD) при пуше в основную ветку

## Установка и запуск (локально)

Для запуска проекта на локальной машине используется Docker Compose, который поднимает все необходимые сервисы.

**Требования:**
- Docker
- Docker Compose

**Шаги запуска:**

1.  **Клонируйте репозиторий:**
    ```bash
    git clone <URL репозитория>
    cd pythonproject14
    ```

2.  **Создайте и настройте файл окружения:**
    Скопируйте файл `.env.sample` в `.env`:
    ```bash
    cp .env.sample .env
    ```
    Откройте файл `.env` и укажите необходимые значения, как минимум `SECRET_KEY` и `TELEGRAM_BOT_TOKEN`.

3.  **Запустите проект:**
    ```bash
    docker-compose up --build -d
    ```

После выполнения этих шагов, приложение будет доступно по адресу **http://localhost**. API документация будет доступна по ссылкам:
- **Swagger UI**: http://localhost/swagger/
- **ReDoc**: http://localhost/redoc/

## CI/CD и Автоматическое развертывание

Проект использует GitHub Actions для реализации CI/CD (непрерывной интеграции и развертывания).

### Процесс CI/CD

1.  **Push или Pull Request в `main`**: Автоматически запускается пайплайн.
2.  **Linting**: Код проверяется на соответствие стандартам с помощью `flake8`.
3.  **Build & Push**: Если линтинг прошел успешно, собирается Docker-образ приложения и загружается в Docker Hub.
4.  **Deploy**: Если сборка и загрузка прошли успешно (и событие - это push в `main`), запускается задача развертывания на удаленном сервере.

### Настройка CI/CD

Для работы пайплайна необходимо настроить следующие секреты в настройках вашего GitHub репозитория (`Settings -> Secrets and variables -> Actions`):

- `DOCKER_HUB_USERNAME`: Ваше имя пользователя в Docker Hub.
- `DOCKER_HUB_TOKEN`: Токен доступа для Docker Hub.
- `SSH_HOST`: IP-адрес или домен вашего удаленного сервера.
- `SSH_USER`: Имя пользователя для подключения к серверу по SSH.
- `SSH_PRIVATE_KEY`: Приватный SSH-ключ для доступа к серверу.
- `DEPLOY_PATH`: Абсолютный путь к директории проекта на сервере.
- `ENV_FILE_CONTENT`: Полное содержимое `.env` файла для продакшн-среды.

### Первоначальная настройка сервера

Ваш удаленный сервер должен быть подготовлен к развертыванию:

1.  Установите **Git**, **Docker** и **Docker Compose**.
2.  Клонируйте репозиторий в директорию, указанную в секрете `DEPLOY_PATH`.

После этого, при каждом пуше в ветку `main`, GitHub Actions автоматически подключится к серверу, обновит код, загрузит новый Docker-образ и перезапустит сервисы.
